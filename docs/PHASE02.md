# Phase 02 — 人生车站交互原型

本次以用户明确的 Phase 02 范围为准，阅读最终 Product PRD 后继续使用现有 Vite + TypeScript + Canvas 2D 架构。没有重做车站、替换小迟素材或改动核心摇杆操作。

## 范围与结构

- 同一个车站内沿轨道布置五个入口，由左至右：社畜号、学术号、编制号、留子号、待机号。镜头跟随移动，不必把五个入口挤在一屏。
- 一名可对话站务员、原有公告牌，以及三名循环经过的背景 NPC。背景 NPC 只制造氛围，不参与碰撞、寻路或剧情。
- `InteractionSystem` 统一处理 id、type、target、range、prompt、icon、action。范围内选择较近目标，接近交界时保留少量稳定余量；真正按下按钮时重新检查距离。
- `DialogueSystem` 用节点、短句和选项定义内容，可继续、分支、关闭。系统不依赖路线或页面组件。
- 游戏分为 exploring、dialogue、boarding、complete 四个状态。对话及登车禁用摇杆并清零输入，关闭对话不会复用之前残留的拖动。
- 小屏幕打开对话时按面板实际高度上移场景，让小迟完整留在对话框上方；关闭后恢复原镜头。按钮支持第二根手指松手触发，并抑制随后可能生成的重复 click。
- 登车约 1.25 秒，先对齐车门，再向前行走并淡出。完成后才记录 `initialRoute`，显示短完成状态，不载入后续路线。
- Route 字段包含 `id / name / trainName / displayName`，另有场景用配色。ID 按本次要求使用 `employment / postgrad / civil_service / abroad / gap`，优先于旧文档中的其他命名。
- `initialRoute` 保留第一次登车，`currentRoute` 可以后续更新。当前均仅在内存中，刷新重置，没有引入存档。

## 手机验收顺序

1. 手机与开发电脑连接同一个 Wi-Fi，打开开发服务的 Network 地址；应直接进入人生车站。
2. 左侧按住拖动，确认四向、斜向、松手停止、碰撞与边界仍正常；可看到背景 NPC 经过及短气泡。
3. 靠近站务员，右侧出现“对话”；走远后隐藏。对话可选择分支、点击继续、关闭后继续走动。
4. 走到上方站台，再向左右探索。五个编号站牌均能查看路线信息，车门均能触发“同学，上不上？”。
5. 先选“我再看看。”，确认不记录路线且可以移动；再选“上。”，确认角色走向车门、淡出、出现对应列车的完成提示。
6. 刷新后尝试其他列车。没有路线正式剧情、传统路线确认菜单、属性、手机或存档界面。
7. 左手按住摇杆时，右手点交互按钮，确认角色立即停止。对话按钮能触摸，屏幕不异常滚动或缩放。

开发模式可在浏览器控制台只读检查 `window.__xiaochi.snapshot()`，查看 `mode / initialRoute / currentRoute`。生产构建不提供此接口。
